# Установка узла целиком и приёмка

Документ описывает порядок действий для `bootstrap.sh` — установки всего стека на голую
Ubuntu 22.04/24.04 `amd64` шестью этапами, — и чек-лист, по которому проверяют, что узел действительно работает.
Про сами параметры и механику разделов читай `README.md`.

## 1. Что нужно до запуска

- Root-доступ к узлу по SSH (пароль или ключ — на ваше усмотрение, скрипт ничего в `sshd_config` не пишет).
- Адрес, с которого вы подключаетесь. В терминале искать его заранее не нужно: `bootstrap.sh` смотрит у
  `sshd`, откуда к узлу подключены, показывает этот адрес и спрашивает, внести ли его в `ignoreip`
  fail2ban; там же можно добавить ещё один или несколько адресов. Заранее он нужен в двух случаях:
  не-терминальный запуск (`ssh -T` без pty, CI, pipe) — там спросить негде, и без `OPERATOR_IPS` этап
  `fail2ban` останавливается, потому что при `maxretry = 2` jail'ы забанили бы самого оператора; и прогон
  из консоли хостера, где SSH-сессии нет и узел ваш адрес увидеть не может.
- Свободные ~4 ГБ на диске (пакеты, образ Docker, два бинарника) и терпение: полный прогон на
  быстром канале — около минуты, медленнее — до нескольких минут.
- Если хостер даёт интерфейс или адрес, отличный от ожидаемого, их можно переопределить: `UPLINK`
  (имя внешнего интерфейса) и `PUBLIC_HOST` (адрес, который попадёт в ссылки клиентов). Всё остальное —
  порты, сеть `10.66.0.0/24`, подменный домен — закреплено значениями по умолчанию и меняется до запуска.

## 2. Прогон

```bash
tmux new -As boot                                          # создать сессию или войти в существующую
NEEDRESTART_MODE=a apt-get update && apt-get install -y git curl tmux
git clone https://github.com/dimmaust/awg_hestera_webpanel.git /root/awg-panel-src
cd /root/awg-panel-src
./bootstrap.sh                                              # адрес для ignoreip скрипт спросит сам
OPERATOR_IPS=203.0.113.10 sudo -E ./bootstrap.sh            # без терминала: pipe, CI, `curl | bash`
```

Команды — по одной, не вставкой блока. Пока `apt-get` ставит пакеты, с терминала читает не шелл:
`needrestart` после установки и сам tmux-клиент забирают очередь ввода себе, и последняя строка
вставки — `./bootstrap.sh` — не исполняется. Проверить, стартовал ли прогон, можно по логу:
`prepare_paths` создаёт `/var/log/awg-panel-bootstrap.log` до первой проверки, так что отсутствие
файла означает, что скрипт не запускался, а не упал. TMux — до `apt-get`, а не после: `new -As`
подхватывает уже существующую сессию, а `new -s` на неё спотыкается.

Опрос выглядит так: узел смотрит адрес подключения у `sshd` — первое поле `SSH_CLIENT`, а если `sudo`
сбросил окружение, пятое поле `who -m`; годится только голый IPv4. Найденное печатается с вопросом
«Внести его в ignoreip?» и принимается по `y` или Enter, отказ — `n`/`н`. Затем по одной строке на
адрес собирает остальное — домашний, рабочий, CIDR подсети; пустая строка заканчивает. Наружные
сервисы определения адреса в опросе не участвуют: с узла они отвечают адресом узла, а не адресом
оператора, и предлагать его в белый список смысла нет. В консоли хостера SSH-сессии нет, поэтому там
вопроса про найденный адрес нет вовсе и список вводят руками. Каждый ответ проходит ту же проверку
формата, что и `OPERATOR_IPS` из окружения, поэтому в `ignoreip` уезжают только IPv4 и CIDR.

Этапы идут в одном порядке: `base → awg → panel → hysteria → telemt → fail2ban`. После каждого —
проверка фактического состояния (`ck`), а не кода возврата пакета; предупреждения (`warn`) считаются
отдельно от провалов. Если этап упал, продолжайте с него же:

```bash
sudo ./bootstrap.sh --stage telemt              # один этап и его проверка
sudo ./bootstrap.sh --skip hysteria             # пропустить этап
sudo ./bootstrap.sh --force-config              # пересоздать узловые конфиги (старые — в .bak)
```

Для DKMS-модуля AmneziaWG на некоторых ядрах нужна перезагрузка. Скрипт сам её не делает: он
останавливается и говорит, что продолжить после. После перезагрузки прогоните недостающие этапы
заново — они идемпотентны.

## 3. Первый вход

Пароль администратора генерируется при первом запуске и лежит в
`/root/awg-panel-secrets/admin-password.txt` (0600). В лог установки секрет не пишется. В конце полного
прогона печатается блок «доступ к панели»: адрес, логин, пароль, предупреждение, что пароль надо сменить
при первом входе, и путь, где его перечитать. Пароль в этом блоке показывается только если его создал
этот же прогон: при прерванном и повторённом запуске наружу уходит лишь строка с путём к файлу.

```bash
sudo cat /root/awg-panel-secrets/admin-password.txt
```

Панель отвечает на `http://<адрес узла>:44090/login`. Первый вход немедленно приводит на страницу
смены пароля: пока `must_change = 1`, ни один раздел не открывается. Смена снимает флаг, сбрасывает
сессию и требует войти новым паролем.

## 4. Чек-лист приёма

Проверяется снизу вверх: сначала «узел жив и всё поднялось», потом «трафик идёт».

| # | Что проверить | Как | Ожидание |
| --- | --- | --- | --- |
| 1 | Все службы после старта | `sudo ./bootstrap.sh --check` | `ИТОГ: провалено проверок — 0`, `warn` только там, где им место |
| 2 | Порт наружу | `ss -tulnp` | `tcp/22`, `tcp/44090`, `tcp/443`, `udp/42511`, `udp/43522`, локальные сокет Docker и agent.sock |
| 3 | Панель | `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:44090/login` | `200` |
| 4 | Права на БД и секреты | `stat -c '%a %U:%G' /opt/awg-panel/data/panel.sqlite3 /root/awg-panel-secrets/admin-password.txt` | `600` на обоих, владелец — root или uid контейнера (имя может не резолвиться — это нормально); битов группы и «всех» на базе быть не должно |
| 5 | Интерфейс AWG | `awg show awg0` | адрес `10.66.0.1/24`, listening `42511` |
| 6 | NAT и форвардинг | `iptables -t nat -S POSTROUTING`, `sysctl -n net.ipv4.ip_forward` | правило MASQUERADE на внешний интерфейс, `ip_forward = 1` |
| 7 | Jail'ы Fail2ban | `fail2ban-client status sshd`, `… status awg-panel`, `… status awg-hy2` | все активны, `Currently banned: 0`, свой адрес в `ignoreip` |
| 8 | Клиент AmneziaWG | профиль из `/users` → Amnezia/HeroKit → `awg show awg0 peers` | peer появился, `latest-handshakes` обновляется, `ping 10.66.0.1` из туннеля проходит |
| 9 | Клиент Hysteria2 | ссылка из `/users` → Hysteria2-клиент | авторизация проходит, в аудите `HY2_AUTH_OK`; после «Выключить» — отказ |
| 10 | Клиент MTProto | ee-ссылка из `/mtproto` → Telegram | бейдж «В СЕТИ» по `current_connections`, трафик идёт |
| 11 | Бэкап | `systemctl start awg-panel-backup.service`, потом `ls -l /var/backups/awg-panel` | архив `0600`, расширение `.enc` |
| 12 | Поведение после перезагрузки | `sudo reboot`, затем пункты 1–7 | всё поднялось само, панель себя не забанила |

Пункт 11 обязателен: `awg-panel-backup.timer` срабатывает в 03:30, и без ручного прогона первый
архив можно не дождаться. Ключ `/etc/awg-panel/backup.key` нужно скопировать с узла сразу — без него
архивы не расшифровать.

## 5. Цена переустановки

Прогон `bootstrap.sh` на уже настроенном узле с `--force-config` пересоздаёт узловые конфиги, а
новая база панели означает, что **все ранее выданные ссылки абонентов мертвы**: профили AWG, ссылки
Hysteria2 и секреты MTProto выпускаются заново, старые ключи перестают работать. Поэтому полная
переустановка — это не «починить узел», а «развернуть новый узел и перевыпустить всё».

Старые конфиги скрипт не удаляет: они уходят в `.bak-<дата>` рядом с оригиналом.
